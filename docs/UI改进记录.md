# 界面与体验改进记录

本轮保留粉紫色校园品牌，参考 Emil Kowalski 的设计方法，改善层级和操作反馈。页面代码、内容与插画由项目实现；参考资料没有作为依赖安装进网站。

| Before | After | Why |
| --- | --- | --- |
| 小字号和浅紫色承担大部分信息 | 系统字体、深色标题、明确字号与间距；重点操作用深紫 | 让搜索、需求和主要动作更容易找到 |
| 列表与右侧长引导列并排 | 列表贯穿内容区，发布引导集中于首屏 | 减少少量内容时的空列 |
| 只有卡片正文是按钮，箭头和底部像另一个入口 | 单一原生按钮覆盖整卡，支持 Tab、Enter、Space | 点击区域一致且可通过键盘使用 |
| 状态仅以文字和圆点区分 | 等待、协作、完成使用文字与不同底色 | 状态不依赖颜色单独传递含义 |
| 刷新列表时反复出现入场动画 | 搜索筛选立即更新，按钮提供轻微按下反馈 | 高频操作保持直接 |
| 无结果和空页面缺少下一步 | 清除筛选、去广场、选身份和查看示例 | 每种空状态都有可执行入口 |
| 全部初始案例等待响应 | 补入带标识的进行中、已完成案例和感谢卡 | 展示完整流程，不冒充真实运营成绩 |
| 概览只能说明待响应数量 | 从真实完成时间统计本周数量，标明演示数据 | 不以固定或虚构数字制造信任 |
| 手机身份标签过长，部分输入字号小 | 紧凑身份入口；触摸设备输入字号至少 16px | 保持操作空间，减少 iOS 输入自动放大问题 |
| 关于内容较长、提示显得警告化 | 四步简述、可展开的范围说明、温暖但明确的共用身份提示 | 保留必要说明，减轻浏览负担 |
| 地点仅在发布时提醒 | 发布字段和线下详情都提示选择校园公共区域 | 交接前也能看到建议 |

## 数据与提交

- 只补入两个独立示例，不替换用户需求、留言或感谢卡；重复启动和部署不会重复插入。
- 本地和线上共享业务规则，云端升级仍通过 revision 条件更新避免覆盖并发写入。
- 本轮按真实开发阶段分别保留功能提交和界面提交，比赛最终提交仍为 GitHub 仓库链接及完整 README。
- 目前已发布公网演示，GitHub 比赛仓库尚未创建或上传，不能用在线演示链接替代比赛仓库提交。

## 验证范围

- 自动业务测试：本地 HTTP 流程、权限与隐私、借用归还、SQLite 上的云端 SQL、并发写入重试、示例升级后保留数据。
- 浏览器：桌面、手机视口、搜索和分类、整卡与键盘操作、弹窗、流程示例、感谢卡、长内容换行、焦点与对比度。
- 已加入减少动态效果、减少透明效果与更高对比度的系统偏好支持。
- 真机边界：未直接操控 iPhone，需在设备上确认软键盘、Safari 地址栏、横屏与安全区域。不能将桌面模拟当成真机验证。
