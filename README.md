# 善意同行

**一点善意，让校园更近一点。**

面向校园日常小需求的互助平台。比赛版本聚焦学习互助、物品借用，让用户完成一次从发布需求到收到感谢的协作。

![互助广场](docs/images/desktop.png)

## 项目背景

校园求助常分散在群聊中，需求容易被刷走，响应后也缺少清楚的进展。我们希望让“谁需要帮助、谁已经响应、事情是否完成”变得明确。

这是一个正在迭代的单人参赛项目。初始需求和账号均为演示数据；没有开展真实校园运营，示例数量不代表实际用户成绩。

## 已实现功能

| 模块 | 实际可用的功能 |
| --- | --- |
| 互助广场 | 两类需求、关键词搜索、按分类筛选、按发布时间或截止时间排序、查看已结束需求 |
| 发布需求 | 标题、说明、线上或线下、公共区域、响应截止时间；借用类额外填写预计归还时间 |
| 演示账号 | 林同学、周同学、许同学三个身份，服务端会话，支持切换与退出 |
| 响应管理 | 提交帮助说明、撤回响应、发起人选定一位帮助者、其他响应同步关闭 |
| 任务协作 | 双方私有文字留言、状态时间线、完成申请、确认完成、说明原因后继续协作 |
| 借用流程 | 出借方确认交付、借用方提交归还、出借方确认收到；归还确认后才能申请完成 |
| 取消与过期 | 未开始的需求可取消；进行中双方协商取消；已交付物品需先确认归还；到期关闭未开始需求 |
| 我的互助 | 查看全部参与、我发布的、我响应的及其最新状态 |
| 感谢卡 | 完成后发起人发送一次感谢，默认只对互助双方可见；单独查看送出或收到的卡片 |
| 本地持久化 | 所有账号共享服务端数据，刷新与重启后保留任务；服务重启后需重新选择演示身份 |
| 手机页面 | 适配窄屏、底部导航、可滚动弹窗、表单验证与操作反馈 |

## 项目特点

- **先找到彼此，再开始行动**：同学响应后需要发起人确认，避免多人重复行动。
- **借用有归还**：物品借用包含交付、归还、确认三个步骤，不能拿到物品就算完成。
- **感谢留给具体的人**：以私有感谢卡记录一次帮助，不设计善良程度排行榜。
- **安装步骤少**：采用 Node.js 内置模块，没有第三方运行依赖，也不需要另外安装数据库。

## 运行环境

- Node.js **24 或以上**，推荐 24 LTS。
- Windows、macOS 或 Linux；浏览器需要支持 HTML dialog，建议使用较新的 Edge、Chrome、Firefox 或 Safari。
- Windows 提供双击启动入口；其他系统使用下方命令。
- 本项目不调用第三方 API，不需要 API Key，不需要购买域名或服务器。

## 安装与启动

### 方法一 Windows 双击启动

下载或克隆整个项目后，双击根目录的 **启动善意同行.cmd**。

启动成功后会打开默认浏览器。请保留启动窗口；关闭窗口或按 Ctrl+C 会停止服务。如果浏览器未自动打开，手动访问：

**http://127.0.0.1:3000**

### 方法二 使用终端

进入项目文件夹，先确认环境：

```sh
node --version
npm --version
```

启动项目：

```sh
npm start
```

也可以直接运行：

```sh
node server.mjs
```

打开 **http://127.0.0.1:3000**。不需要 npm install，不需要构建。

开发时可运行 `npm run dev`，服务器代码变化后会自动重启。网页文件修改后刷新浏览器即可。

### 数据初始化与保存

首次启动自动创建 `data/store.json`，放入 6 条示例需求及其初始状态。后续使用会保存至同一文件，不会每次重启都覆盖。

请仅启动一个使用同一数据文件的服务实例。该 JSON 存储适合本地比赛演示；公开部署、多进程和真实用户规模需要迁移到正式数据库。

`data/` 不会提交到 Git。交付仓库从干净环境首次运行时，会自动生成示例数据。需要从头重新演示时，可先停止服务，将 `data/store.json` 改名备份，再启动。

### 可选环境设置

默认不需要配置。需要更换端口或保存位置时，可在启动前设置：

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| PORT | 3000 | 本地监听端口 |
| DATA_FILE | data/store.json | 指定另一份数据文件，路径相对于启动目录 |
| DEMO_MODE | true | 设为 false 关闭演示登录；目前尚未实现正式注册，此时仅可访客浏览 |
| BROWSER | 自动打开 | 仅双击启动器使用；设为 none 不自动打开浏览器 |

PowerShell 示例：

```powershell
$env:PORT = '3001'
npm start
```

## 完整操作示例

### 演示一 学习互助

1. 点击左下角“选择演示身份”，选择 **林同学**。手机端点击底部“身份”。
2. 点击“发布需求”，选择“学习互助”。标题示例“想请教一道高数题”，填写具体说明和未来的响应截止时间，选择线上交流并发布。
3. 关闭详情，切换为 **周同学**，打开刚发布的需求，填写说明并点击“我可以帮忙”。
4. 切换回 **林同学**，打开需求，选择“请这位同学帮忙”。
5. 切换为 **周同学**，到“我的互助”打开任务，在协作区留言，交流完成后点击“这次帮助完成了”。
6. 切换为 **林同学**，到“我的互助”打开任务，确认完成并填写感谢。
7. 切换为 **周同学**，进入“我的感谢卡”，查看刚刚收到的感谢。

如果两个浏览器同时演示，分别登录不同身份即可。完成另一端操作后，刷新页面或重新打开任务详情查看最新进展。

### 演示二 借一把雨伞

1. 林同学打开初始需求“想借一把伞，陪我走过这场雨”。
2. 周同学响应，林同学确认周同学作为帮助者。
3. 周同学在协作区点击“已当面交付物品”。
4. 林同学点击“我已归还物品”。
5. 周同学点击“确认收到归还物品”，然后提交完成申请。
6. 林同学确认完成并发送感谢。

没有完成归还确认时，不能直接把借用任务标为完成。

### 演示三 多人响应与权限

周同学和许同学分别响应同一需求。林同学只能选定一位；确认后其他响应关闭。未被选中的用户无法阅读双方协作留言或感谢内容。

## 功能状态

```text
待响应 → 待确认 → 进行中 → 待确认完成 → 已完成 → 发送感谢
    ↘ 取消或过期
```

进行中的需求不会因为原响应截止时间到了就自动取消或自动完成。进行中取消需对方同意；借用物品交付后还需确认归还。发起人认为未完成时，可以说明原因并退回继续协作。

## 技术结构

- 前端：HTML、CSS、原生 JavaScript，响应式布局及原生 dialog。
- 服务端：Node.js HTTP 服务、随机会话令牌、HttpOnly 和 SameSite Cookie、服务端权限与状态校验。
- 存储：同步写入临时 JSON 后替换正式文件，单进程串行处理状态修改；写入失败回滚内存状态。
- 测试：Node.js 内置测试框架，通过实际 HTTP 请求验证两个账号之间的流程。

campus-kindness/
├── public/                网页、样式、交互和图标

## 已知限制与后续规划

- 当前是**本地比赛演示版**，服务只监听 127.0.0.1；另一台电脑或手机不能直接访问此地址。手机页面已验证，但跨设备访问与部署尚未配置。
- 三个账号为任何体验者都能选择的**演示身份**，不能代表真实身份认证；不要存放真实私密信息。公开试用前需替换为正式账号系统。
- 会话保存在内存中，服务器重启后需要重新选择身份。
- 数据文件适合单个进程使用，暂不支持并发进程、正式数据库备份或云端同步。
- 无实时聊天和推送；重新打开详情、刷新或回到页面时更新状态。
- 暂不支持需求编辑、附件上传、举报后台、校内身份验证、地图、积分、外部通知和多人活动。
- 感谢卡暂不支持导出图片和公开分享。
- 早期 Word 策划书包含长期候选功能，本次已实现范围以本 README 和实际可运行版本为准。

下一轮创新候选：几分钟的小善举、可自愿参与的善意接力、帮助偏好匹配。先验证需求，再选择少数功能实现。

## 常见问题

**页面打不开？** 先确认启动窗口仍在运行，再访问启动窗口显示的地址。不要直接双击 public/index.html，网页需要通过服务运行。

**端口被占用？** 如果已经启动过项目，使用原来的窗口即可；否则关闭占用程序或通过 PORT 改用 3001 等端口。

**切换身份后找不到进行中的需求？** 默认广场只显示仍可响应的需求。请到“我的互助”查看，或在广场启用“同时查看已结束的需求”。

**npm 命令被 PowerShell 限制？** 可以运行 `npm.cmd start`，或双击启动入口，不需要修改系统执行策略。
